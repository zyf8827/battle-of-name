# 姓名大作战 (Name Battle) - 游戏策划文档

> **版本**: 0.2 (机制迭代)
> **日期**: 2026-02-11
> **状态**: 架构规划完成，开发启动中

## 1. 游戏概述 (Overview)
**核心玩法**: 输入两个姓名 -> 生成唯一角色属性 -> 进行回合制自动对战。
**核心特色**: 
- **姓名即命运**: 同样的姓名永远生成相同的初始属性（基于 Hash 算法）。
- **Roguelike 战斗**: 每次战斗过程引入独立随机种子，包含随机事件、Buff/Debuff、暴击闪避等变数。
- **快节奏博弈**: 无升级成长系统，专注于单局内的天赋、装备与状态博弈。

## 2. 游戏风格 (Style & Theme)
- **世界观**: **万物皆可梗 / 现实魔幻主义 (Reality Satire & Absurdism)**。
    - 不局限于职场或 IT 圈，涵盖社会百态、网络热梗、抽象概念、甚至无机物。
    - 核心基调是 **欢乐、恶搞、讽刺**。打破第四面墙，让玩家会心一笑。
    - *示例*: 【键盘侠】使用技能 "道德绑架" (精神伤害)；场景突变为 "相亲角" (单身狗受到持续暴击)。
- **视觉风格**: **精美排版纯文字 UI (Text-Based UI)**。
    - 极简但富有张力的文字表现。
    - 界面需体现“现代”、“极客”感，同时兼容“土味”与“高大上”的反差萌。
- **战斗节奏**: **自动播报 (Auto-Battler)**。
    - 类似 MUD 的实时战斗日志滚动，支持倍速、暂停。

## 3. 核心机制 (Core Mechanics)

### 3.1 属性系统 (Attributes)
*游戏去除魔法值 (MP) 设定，技能释放仅受冷却时间 (CD) 或特殊消耗 (如扣血) 限制。*

- **力量 (STR)**
    - **作用**: 提升物理攻击力 (Attack)。
    - **风格**: “大力出奇迹”。
- **敏捷 (AGI)**
    - **作用**: 决定出手速度 (Speed)。
    - **风格**: “天下武功唯快不破”。
- **体质 (VIT)**
    - **作用**: 决定最大生命值 (Max HP)。
    - **风格**: “活着才有输出”。
- **幸运 (LUK)**
     - **作用**: 影响随机事件判定优劣 (Event Roll)、掉落质量，并对部分战斗概率提供“微调”。
    - **风格**: “欧皇”与“非酋”的分水岭。高幸运角色容易在随机事件中获得增益，反之易遭殃。

#### 3.1.1 幸运的平衡规则 (LUK Balance Rules)
为避免 LUK 同时支配“战斗强度”和“事件走向/掉落收益”导致“一属性统治”，数值设计采用以下约束：

1. **拆分为两条影响曲线（对玩家仍展示为 LUK）**
    - **EventLuck**: 只用于随机事件、掉落品质、少量“非战斗收益”的判定。
    - **CombatLuck**: 只对战斗概率做“微幅偏置”（例如暴击/闪避/异常触发的边际提升），不得作为主决定因素。

2. **软上限（Diminishing Returns）**
    - EventLuck、CombatLuck 均采用“边际递减”曲线：低~中 LUK 提升明显，中~高 LUK 主要提升稳定性而不是上限爆炸。

3. **战斗概率主属性归位**
    - 暴击率的“基础部分”由常量与职业/装备决定；LUK 只做偏置。(MVP暂未实装闪避)
    - 随机事件的好坏倾向由 EventLuck 主导，但强负面事件保留最低触发概率（避免“欧皇免疫所有坏事”）。

> 实现公式与标签口径以引擎文档为准，保证策划与程序一致。

### 3.2 战斗流程 (Combat Loop)
- **资源**: 仅 **HP (生命值)**。无 MP，技能改为 **CD (冷却) 制**。
- **流程（以引擎 `Time & Loop` 为准）**:
    1. **回合开始快照 (Snapshot @ RoundStart)**: 记录当前状态，用于“时光倒流”等回滚类机制。
    2. **回合开始钩子 (onRoundStart)**: 触发环境与双方单位的回合开始逻辑。
    3. **环境事件窗口：RoundStart（可选）**: 随机事件可在回合开始触发（如突发剧情/强制停手类）。
    4. **冷却结算（回合制 CD）**: 技能/主动装备等 CD 统一按“回合”递减，避免因行动次数差异导致不公平。
    5. **生成行动队列（按 AGI 稳定排序）**: 存活单位按敏捷排序依次行动；相同敏捷用稳定规则兜底。
    6. **依次执行每个单位的行动 (Turn)**:
        - **onTurnStart**: 行动开始触发。
        - **状态结算**: 处理 DoT、护盾衰减、控制检查等。
        - **行动判定**: 若被控制则跳过行动。
        - **决策并执行 Action**: 产出一个或多个事件，走引擎事件管道（拦截 -> 结算 -> 反应，DFS）。
        - **onTurnEnd**: 行动结束触发。
    7. **回合结束钩子 (onRoundEnd)**: 触发环境与双方单位的回合结束逻辑。
    8. **持续时间递减与移除 (Duration Tick @ RoundEnd)**: 所有 `duration > 0` 的 Buff/Debuff 在回合结束统一递减，到 0 则移除。
    9. **环境事件窗口：RoundEnd（可选）**: 随机事件也可在回合结束触发（如收尾结算、气氛转折）。

> 说明：随机事件属于“环境（ENV）修饰器”的行为，只允许发生在预定义窗口（RoundStart / RoundEnd），以保证同 seed 可复现。

### 3.3 职业系统 (Class System)
- **机制**: **模版 + 天赋 (Template + Talents)**。
- **天赋消耗**: 
    - 大部分天赋为 **CD 制** (如 3回合冷却)。
    - 强力天赋可消耗 **HP** (如“献祭”类技能)。
    - *示例*: **[内卷]** (主动): 消耗 10% 当前 HP，本回合攻击力翻倍。

### 3.4 装备系统 (Equipment System)
- **机制**: **混合模式 (本命 + 拾取)**。
- **装备类型**:
    - **被动装备**: 提供属性加成 (如 幸运+10)。
    - **主动装备**: 拥有独立 CD。
        - *示例*: **[指尖陀螺]**: CD 3回合。造成多段敏捷伤害。

### 3.5 技能连携与机制 (Interaction Mechanics)
- **机制**: **机制互动流 (Interaction & Combo)**。
- **描述**: 技能之间存在逻辑克制与连携。
- **示例**:
    - **【杠精】** 使用 `[偷换概念]` (主动天赋)，将受到的魔法伤害转化为物理治疗。
    - **【舔狗】** 使用 `[自我感动]` (主动天赋)，牺牲 30% HP，给对手增加 Buff `[被爱]` (无实际效果，纯嘲讽)。
    - **【微商】** 使用 `[喜提和谐号]` (主动天赋)，召唤巨型载具冲撞（需蓄力3回合）。

### 3.6 随机事件 (Random Events)
- **频率**: **混乱战场 (High Frequency)**。
- **机制**: 每 3-5 回合极大概率触发全场事件。
- **示例**:
    - **[全员核酸]**: 双方停止攻击 1 回合，进行健康检测。
    - **[股市熔断]**: 双方金币/积分清零（如果有），或者士气低落（全属性-10%）。
    - **[作者没灵感了]**: 这一回合跳过，并在公屏打出一行省略号。

### 3.7 胜利条件 (Victory Condition)
- **机制**: **HP 归零 (Deathmatch)**。
- **描述**: 无论遭遇何种精神打击，HP <= 0 判负。

### 3.8 文本播报与文案系统 (Narration & Log)
**目标**: 不增加页面/交互复杂度，仅通过“同一事件多模板 + 同义句池 + tags 驱动”提升戏剧性与复玩观感。

- **事件 -> 文案的驱动因子**: 以事件 tags 为主（如 `crit` / `miss` / `reflect` / `dot` / `heal` / `immune`），同一事件不同 tags 走不同模板。
- **同义句池 (Synonym Pool)**: 每条模板允许配置 3~10 条同义句；抽取时采用“短期去重”避免刷屏重复。
- **语气与风格包 (Tone Pack)**: 文案库按叙事标签分组（职场/抽象/土味/高大上/二次元…），允许玩家选择默认风格包（不影响数值，仅影响播报文本）。
- **防重复策略（轻量）**: 同一回合内同一模板不重复；连续多次触发同类事件时强制换句。

> 引擎侧需提供：事件 tags、关键数值（伤害/治疗量）、主体名称、来源（技能/装备/环境）等，供模板渲染。

## 4. 技术栈规划 (Tech Stack)
- **Core**: React 18 + TypeScript + Vite
- **Styling**: Tailwind CSS (UI/Layout)
- **Animation**: Framer Motion (Text effects, transitions)
- **State Management**: Zustand (Simple global state)
- **Utils**:
    - `seedrandom`: 核心库，用于基于姓名生成确定性随机数。
    - `clsx` / `tailwind-merge`: 动态样式类名处理。
    - `uuid`: 生成唯一战斗ID。

## 5. 开发路线图 (Roadmap)
1.  **脚手架搭建**: Vite + React + TS + Tailwind 初始化。
2.  **核心算法实现**: 编写 `Name -> Stats/Class` 的生成逻辑 (Hash算法)。
3.  **战斗引擎开发**: 实现回合制循环、技能判定、Buff结算。
4.  **UI 开发**: 制作战斗日志组件、属性面板、输入框。
5.  **内容填充**: 编写大量的职业、技能、事件文案库 (JSON配置)。

## 6. 内容创意库 (Content & Creative Ideas)
*本章节用于记录各种脑洞，供开发时扩充文案库使用。*

### 6.1 职业 (Classes)
- **现实生活**: 外卖骑手 (加速/冲撞)、托尼老师 (削减对方防御/剪坏发型)、驾校教练 (精神攻击/嘲讽)。
- **网络生物**: 键盘侠 (远程喷子)、乐子人 (混乱中立/随机效果)、欧皇 (全属性波动极大)。
- **非人类**: 还是那个Bug (不可选中/随机报错)、薛定谔的猫 (生死叠加态/闪避极高)。
- **抽象概念**: 周一 (全场Debuff/减速)、DDL (死亡倒计时/爆发伤害)。

### 6.2 物品/装备 (Items)
- **武器**: 键盘 (物理伤害)、平底锅 (格挡远程)、折叠凳 (隐藏武器/攻速慢)。
- **防具**: 痛苦面具 (受伤回蓝)、皇帝的新衣 (防御力0但增加闪避/因为看不见)。
- **消耗品**: 肥宅快乐水 (回血/加快乐值)、后悔药 (重置上一回合，极稀有)。

### 6.3 场景/事件 (Environments & Events)
- **社会性死亡**: 随机公开一方的“浏览器历史记录”，造成巨额精神伤害 (MP归零)。
- **网抑云时间**: 到了午夜12点，双方进入抑郁状态 (攻击力大幅降低，防御力提升)。
- **真香定律**: 一方发誓不使用技能后，下一回合强制使用且威力翻倍。

### 6.4 内容标签与规范 (Content Tags & Conventions)
为保证内容可扩展、可组合且不互相“打架”，所有技能/装备/Buff/事件必须声明标签与强度分级。

- **战斗标签 (Combat Tags)**: `physical` / `magic` / `true_damage` / `dot` / `heal` / `shield` / `control` / `reflect` / `crit` / `miss` / `immune` …
- **叙事标签 (Narrative Tags)**: `office` / `dating` / `abstract` / `meme` / `wholesome` / `toxic` …（用于风格包过滤）
- **强度等级 (Power Tier)**: `S/A/B/C`（只用于平衡评审与内容筛选，不直接参与数值）

> 标签、叠加规则、优先级与冲突策略以引擎文档为准。
